# PriceWatch - границы продукта

## Назначение
PriceWatch автоматически проверяет цены выбранных товарных предложений в интернет-магазинах, сохраняет подтвержденные наблюдения и уведомляет пользователя в Telegram при существенном снижении цены.

Проект учебный, но должен быть практически применимым и структурированным как небольшое реальное приложение, а не одноразовый демонстрационный скрипт.

## Целевая аудитория
1. Покупатели, которые хотят дождаться выгодной цены или акции.
2. Малый бизнес, которому нужен простой мониторинг публичных цен конкурентов.

## Интерфейс MVP
Основной пользовательский интерфейс - Telegram-бот.

Планируемые действия:
- «Мои товары»;
- «Добавить товар»;
- «Импорт CSV»;
- «Экспорт CSV»;
- «Настройки».

Web UI в MVP не входит.

## Модель Product / Offer
`Product` - логический товар глазами пользователя, например `iPhone 16 128 GB`.

`Offer` - конкретное предложение этого товара в одном магазине, определяемое URL.

Пример:

```text
Product: iPhone 16 128 GB
├── Offer: MediaMarkt
├── Offer: PcComponentes
└── Offer: другой магазин
```

Один `Product` принадлежит одному `User`. Один `Offer` принадлежит одному `Product`.

## Названия товаров
`product.name` - понятное пользователю логическое название.

`offer.source_title` - заголовок, извлеченный со страницы магазина.

При ручном добавлении PriceWatch пытается получить `source_title` и предлагает его как название Product, но пользователь может изменить название.

В MVP нельзя автоматически считать товары одинаковыми только по похожим заголовкам разных магазинов. При добавлении еще одного магазина пользователь подтверждает привязку URL к существующему Product.

## CSV - обязательная функция MVP
Поддерживаются импорт и экспорт CSV.

Минимальный формат импорта:

```csv
product_name,url
iPhone 16 128 GB,https://example.com/product
```

Строки с одинаковым нормализованным `product_name` относятся к одному Product.

Правила сопоставления MVP:
- убрать пробелы по краям;
- сравнивать без учета регистра;
- fuzzy matching не использовать.

Импорт частичный: ошибка одной строки не должна откатывать успешно обработанные строки.

Дубликат нормализованного URL у того же пользователя пропускается и отражается в отчете, но не делает весь импорт ошибочным.

Категории результата импорта могут включать:
- `IMPORTED`;
- `DUPLICATE`;
- `BLOCKED`;
- `AMBIGUOUS`;
- `INVALID`.

Валидный URL разрешено сохранить даже тогда, когда при первой проверке не удалось надежно получить цену. Подробности - `BUSINESS_RULES.md`.

Рекомендуемые колонки экспорта:

```csv
product_name,store,url,current_price,currency,last_checked,status
```

Экспорт полной истории цен в MVP не обязателен.

## Нормализация URL
Хранить исходный и нормализованный URL.

Для MVP:
- hostname привести к lowercase;
- удалить fragment;
- удалить известные tracking-параметры `utm_*`, `gclid`, `fbclid`;
- функциональные query-параметры сохранить, так как они могут определять вариант товара.

## Расписание
Автоматический мониторинг выполняется один раз в день с помощью библиотеки `schedule`. Конкретное время и timezone фиксируются при реализации scheduler.

## Вне MVP
- Web UI.
- Автоматическое fuzzy-сопоставление товаров между магазинами.
- Конвертация валют.
- Сложные графики - текстовой истории достаточно.
- Набор site-specific парсеров.
- Обход CAPTCHA/anti-bot.
- Микросервисы, очереди и распределенная инфраструктура.
- Накопительная `reference_price`-логика как замена обязательному сравнению с предыдущей ценой. Ее можно рассматривать только как будущее улучшение после выполнения исходного задания.
